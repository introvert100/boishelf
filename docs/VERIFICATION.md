## PDF preview compatibility — 7 October 2026

After the signed upload fix, the owner confirmed the PDF uploaded but the admin viewer and preview generator rejected it with the same generic “corrupt, encrypted, or unsupported” text. The actual book bytes were not available for local inspection. The old code treated every `pdf-lib` parse failure as a bad PDF. A reproduced PDF that opens without a password triggers this failure; QPDF reads it and extracts only the requested first pages. The server now tries the existing fast PDF copy first, then uses a pinned QPDF WASM fallback when that parser fails. The fallback starts from an empty document, selects only the requested pages, strips annotations, verifies the output page count, and keeps the last paid page private. Password-required and unreadable PDFs still fail, with more accurate messages. Preview errors now log a request ID and route without private paths.

The regression test covers the original parser failure, page boundaries, and a password-required PDF. A 38.5 MB synthetic, 80-page PDF produced a 10-page excerpt under a 384 MB V8 heap; a fresh process reported 141 MB RSS after completion. This is not a guarantee for every image-heavy file on Render’s 512 MB free instance. No migration or Supabase setting is needed. Verify the owner's uploaded PDF through the admin viewer and save a preview after the new deploy; roll back the app commit if memory or extraction errors appear. The existing paid PDF remains private and unchanged.
