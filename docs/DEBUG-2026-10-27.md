# Delivery districts and payment controls

## Request and evidence

The owner requested bKash and COD checkout, a district selector with separate delivery fees, and Dhaka-only delivery initially. The screenshot showed the old fixed Dhaka (50 BDT) / outside-Dhaka (100 BDT) form. Code inspection found both the quote and atomic order RPC used that two-zone model; the payment switches required Render environment edits.

A read-only browser check of readandrich.com on 27 October 2026 confirmed the homepage responds, but all five rendered policy pages still say the policy is unpublished. The owner confirmed policies/business setup are not yet ready. Do not claim real checkout is open. No real order, payment or customer information was used in testing.

## Changes

- New append-only migration `20261027160200_district_delivery_checkout_controls.sql`: service-only delivery districts under RLS, initially Dhaka at the saved fee (50 BDT fallback), atomic replacement and physical-order fee lookup. Shared/exclusive settings-row locks serialize orders against fee-list replacement. Existing order snapshots and retries survive changes/removal.
- Admin → Printed & delivery: select, add, remove and price districts; explicit save and success notification. Empty lists close printed checkout. The buyer selector uses only saved districts, while both API and database reject unsupported destinations and stale totals.
- Admin → Payments: audited bKash/COD switches and business/courier attestations. Both switches are requested on by the migration, as instructed; attestations bootstrap existing environment confirmations until the owner saves them. All existing policies, owner, catalogue, stock and receiving-number gates remain. Failed database reads cannot fall back to stale settings. Pausing checkout does not block existing order review/fulfillment.
- The physical-order RPC now rejects newly ordered mixed bundles while preserving historical mixed-order fulfillment. Tests explicitly seed historical orders with the previous RPC and restore the current RPC before exercising fulfillment.
- Deployment/operations instructions replace obsolete Render payment flags with the admin controls. Environment attestations remain optional bootstrap values; a saved false always overrides them.

## Rollout and rollback

Apply the migration before deploying app code. Publish final bilingual policies and confirm the business number/courier in Admin → Payments; check the displayed availability status. Verify a controlled COD order and manual bKash transfer/review/download before announcing sales.

To pause new orders, turn both payment switches off and save. If Admin is unavailable, run `update public.payment_settings set bkash_enabled=false,cod_enabled=false where id='default';` in the privileged SQL Editor. Keep existing orders and private files intact. Do not roll back to two-zone checkout code while new district fees are in use; it can display obsolete quotes. Retain the migration and prefer a forward fix. If an old application rollback is essential, first disable its legacy Render flags too.
